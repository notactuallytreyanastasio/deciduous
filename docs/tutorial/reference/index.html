CLI Reference

CLI Reference

Every command and flag in deciduous 1.1.0, from the binary's own --help on 2026-10-24. If a flag is not here, the binary does not have it.

Commands

CommandDoes
initInitialize deciduous in the current directory, then ask where the graph lives
updateUpdate assistant integration files to the binary's version
check-updateCompare .deciduous/.version with the binary; exit 1 if an update is needed
auto-updateDeprecated: prints that version checking is always on
addAdd a node
link / unlinkAdd or remove an edge
deleteDelete a node and its edges
statusSet a node's status
promptSet or replace a node's prompt
nodes / edges / showList nodes, list edges, show one node
graphFull graph as JSON on stdout
serveWeb viewer (or the multi-graph API daemon with --api)
syncReconcile .deciduous/graph.json with the local database, both directions
backupCopy the database
commandsRecent command log
dot / writeupDOT (and PNG) export; PR writeup in Markdown
migrateAdd change_id columns to a pre-0.10 database
auditAssociate commits with nodes by matching titles to commit messages
pulseActive state, gaps and health
narrativesinit, show, pivots for .deciduous/narratives.md
archaeologypivot, timeline, supersede
transcriptimport, list: build the graph from a Claude Code transcript
roadmapSync ROADMAP.md with GitHub Issues
hooksinstall, status, uninstall the hooks listed in config.toml
integrationClaude Code integration status
opencodeinstall, status, uninstall the OpenCode integration
docDocument attachments
themes / tagTheme definitions; tagging nodes with them
boardMessage board for agents working at the same time
mcpLocal MCP server on stdin/stdout
remoteConfigure and use a shared graph server
completionShell completions

Not in 1.1.0, though older docs mention them: edit, diff (export/apply/status), events (hidden; prints that sync replaced it), nodes --status. Every argument that names a node accepts a local integer id, a prefix of the change id, or a server id.

Setup

deciduous init [--claude] [--opencode] [--windsurf] [--both] [--no-auto-update]
    --claude            Claude Code (.claude/, CLAUDE.md); the default
    --opencode          OpenCode (.opencode/, AGENTS.md)
    --windsurf          Windsurf (.windsurf/)
    --both              Claude Code and OpenCode
    --no-auto-update    Accepted and ignored; version checking is always on

deciduous update [--all <DIR>]
    --all <DIR>         Update every deciduous project directly under DIR (and DIR itself)
    Files deciduous wrote are replaced; files someone else wrote are kept (Markdown gets the
    new text appended in a marked block). Backs up to .deciduous/update-backups/<time>/.
    Never touches .deciduous/config.toml or docs/; with a [remote], leaves .gitignore,
    .gitattributes, .git/config and graph.json alone.

deciduous check-update          exit 0 up to date, 1 update needed
deciduous auto-update <on|off>  deprecated, no effect
deciduous completion <bash|zsh|fish|powershell|elvish>

Nodes and Edges

deciduous add <TYPE> <TITLE> [OPTIONS]
    TYPE                goal | option | decision | action | outcome | observation | revisit
                        (--help lists six; revisit is accepted)
    -d, --description   Description (observations warn when it is missing)
    -c, --confidence    0-100
        --commit        HEAD, a branch, a tag, origin/main, a hash or a prefix; stored as the
                        full hash; a rev git cannot resolve is refused
    -p, --prompt        Prompt that triggered this node
        --prompt-stdin  Read the prompt from stdin
    -f, --files         Comma-separated files
    -b, --branch        Git branch (auto-detected)
        --no-branch     Do not detect the branch
        --date          RFC3339, "YYYY-MM-DD" or "YYYY-MM-DD HH:MM:SS"; backdates the node

deciduous link <FROM> <TO> [-r RATIONALE] [-t EDGE_TYPE]
    -t                  leads_to (default) | requires | chosen | rejected | blocks | enables |
                        took_from (this node borrowed from that one, usually across branches)
    Refuses a self-loop and an edge that would make two nodes each other's parent.

deciduous unlink <FROM> <TO> [-t EDGE_TYPE]
    -t                  Required when the two nodes are joined by more than one edge type

deciduous delete <ID> [--dry-run]
deciduous status <ID> <STATUS>
    STATUS              pending | active | completed | rejected | superseded | abandoned
                        (--help lists four; all six are accepted)
deciduous prompt <ID> [PROMPT]        omit PROMPT to read stdin

Archaeology and Narratives

deciduous archaeology pivot <FROM_ID> <OBSERVATION> <NEW_APPROACH> [-c CONF] [-r REASON] [--dry-run]
    Creates observation -> revisit -> new decision under FROM_ID and marks FROM_ID superseded.
    No --date: the three nodes carry today's date.
deciduous archaeology supersede <ID> [--cascade] [--dry-run]
    --cascade           Also mark every descendant superseded

deciduous narratives init [-o OUTPUT] [--force]     one section per active goal
deciduous narratives show [-p PATH]
deciduous narratives pivots [-b BRANCH] [--json]

Transcripts

deciduous transcript import <TRANSCRIPTS>... [--dry-run] [--no-hash] [--json]
    TRANSCRIPTS         Paths to .jsonl files, or session ids looked up under
                        ~/.claude/projects/<this project>/ (any prefix of the file name)
    --dry-run           Print the counts, write nothing
    --no-hash           Do not hash the files the actions touched
    --json              The report as JSON, one object per transcript
    Importing the same transcript again changes nothing.

deciduous transcript list [--dir DIR] [--json]
    --dir               Directory holding the transcripts (default: this project's
                        ~/.claude/projects/<slug>/)

Viewer and MCP

deciduous serve [-p PORT] [--api] [--data-dir DIR] [--token TOKEN] [--bind ADDR]
    -p, --port          default 3000
    --api               Multi-graph JSON API daemon instead of the viewer
    --data-dir          API mode: graphs/<id>/deciduous.db under here (or DECIDUOUS_API_DATA_DIR)
    --token             API mode: bearer token (or DECIDUOUS_API_TOKEN)
    --bind              API mode: default 127.0.0.1

deciduous mcp           MCP server on stdin/stdout; client config {"command": "deciduous", "args": ["mcp"]}

The Shared Server

deciduous remote setup [--local] [--url URL] [--port PORT] [--database-url URL] [--docker-postgres] [--docker]
    The same question init asks, with flags to answer it in a script:
    --local             This machine's server; PostgreSQL on localhost:5432 as $USER
    --database-url      This machine's server against the PostgreSQL you name
                        (postgres://USER[:PASSWORD]@HOST[:PORT]/DATABASE[?sslmode=...])
    --docker-postgres   A new PostgreSQL in Docker (implies --docker)
    --docker            This machine's server in Docker instead of a background service
    --url               A server someone else runs (token from DECIDUOUS_MCP_TOKEN or the stored one)
    --port              First setup only; afterwards ~/.config/deciduous/server/.env stands

deciduous remote login [--url URL]      token from stdin, stored in ~/.config/deciduous/credentials (0600)
deciduous remote logout
deciduous remote init <URL> [--workspace NAME]     point this project at a server (lower-level than setup)
deciduous remote status                 how far the local database has drifted from the server
deciduous remote pull                   refresh the local database from the server
deciduous remote push [--drop-rejected] [--retry-rejected] [--drop OP_ID] [--seed] [--overwrite]
                      [--repair] [--overwrite-server]
    --seed              Also send nodes, edges and documents the server lacks that no op covers
    --overwrite         Send the whole local graph over the server's copy (pre-1.0.3 behaviour)
    --repair            Also send fields this copy changed and never logged
deciduous remote adopt [ROOT] --url URL [-n]       configure every project under ROOT
deciduous remote watch [--url] [--claude-code] [--types T,T] [--branch B]... [--edges] [--json]
    One line per write as it lands; --url prints the socket URL; --edges adds edge events

The Message Board

deciduous board post --subject TEXT [-m BODY] [--as LABEL] [--reply-to ID] [--branch B] [--json]
    @label anywhere in subject or body addresses it; body from stdin when -m is omitted;
    --as defaults to $DECIDUOUS_AGENT_LABEL
deciduous board read [--since ID] [--from LABEL] [--to LABEL] [--unanswered LABEL] [-q TEXT] [--limit N] [--json]
deciduous board show <ID> [--json]
    Kept in the main worktree's database, or on the server with a [remote]. Never in graph.json.

Node Types, Edge Types, Statuses

Node typeMeaning
goalWhat is being attempted; root goals carry the prompt
optionAn approach considered, under a goal
decisionThe choice; the chosen option points at it with chosen
actionWork done, often with -f files and a commit
outcomeWhat resulted
observationA fact that changes the plan
revisitAn earlier approach reconsidered
 
goal → options → decision → actions → outcomes
observations attach anywhere; a revisit sits between an old outcome and a new decision
Edge typeUse
leads_toDefault; the flow above
chosenoption → decision that took it
rejecteddecision → option it dropped
requiresDependency
blocksSomething standing in the way
enablesSomething made possible
took_fromA borrow: from the node taken from, to the node that used it, usually across branches

Statuses: pending (default), active, completed, rejected, superseded, abandoned. The graph server additionally holds feedback nodes and done statuses from older data, which sync and pull accept but add and status do not create.

Configuration: .deciduous/config.toml

# written by init
[branch]
main_branches = ["main", "master"]
auto_detect = true

[updates]
# Version checking is always-on (once per 24h, non-blocking)

# written by the server step of init, or remote setup / remote init
[remote]
url = "http://127.0.0.1:24871"
workspace = "snowflex"

# optional: your own Claude Code hooks, installed by `deciduous hooks install`
[hooks]
enabled = true

[[hooks.pre_tool_use]]       # or [[hooks.post_tool_use]]
name = "my-hook"
description = "..."
matcher = "Edit|Write"
enabled = true
script = "..."               # or script_path = "hooks/my-hook.sh", relative to .deciduous/

Environment Variables

VariableEffect
DECIDUOUS_DB_PATHPath of the SQLite database to use instead of .deciduous/deciduous.db
DECIDUOUS_MCP_TOKENThe server token; read before ~/.config/deciduous/credentials. Never written to config.toml
DECIDUOUS_AGENT_LABELThis session's board label: default for board post --as, and what board-mentions.sh reads for
DECIDUOUS_NO_SERVERSet to 1: init and update skip the server step (tests, CI)
DECIDUOUS_QUIET_LOCAL_ONLYSet to 1: a write in a project with no server does not print the one-line hint naming remote setup
DECIDUOUS_PORTAnswers remote setup's port question in a script (first setup only)
DECIDUOUS_OPS_TIMEOUTPer-request timeout when replaying operations to the server
DECIDUOUS_API_TOKEN, DECIDUOUS_API_DATA_DIRserve --api: the bearer token and data directory when not passed as flags

DECIDUOUS_ENV_FILE, DECIDUOUS_SERVER_MODE, DECIDUOUS_MCP_INSTALL_DIR and DECIDUOUS_BIND_ADDRESS are written into this machine's server settings (~/.config/deciduous/server/.env and the service unit) by remote setup; they configure the server process, not the CLI.
