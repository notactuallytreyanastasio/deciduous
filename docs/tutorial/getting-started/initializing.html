Initializing on a Project

One command gives your AI assistant a decision graph workflow.

Deciduous is initialized per-project. Navigate to any git repository and run deciduous init. Here we will use a project called snowflex as an example:

deciduous init
cd snowflex deciduous init Created .deciduous/deciduous.db (SQLite database) Created .deciduous/config.toml (configuration) Created .claude/commands/ (9 slash commands) Created .claude/skills/ (3 skills: pulse, narratives, archaeology) Created CLAUDE.md (project instructions) Created docs/ (GitHub Pages viewer) Ready! Run /decision-graph to graph existing history, or just start working.

That single command scaffolds everything deciduous needs. Let's walk through what each piece does.

What Gets Created

.deciduous/deciduous.db — The Graph Database

This is the SQLite database that stores your decision graph: every node, edge, status, confidence score, prompt, and commit link. It lives locally and is gitignored by default. Each developer on a team has their own copy, and decisions are shared through the patch/sync system rather than by committing the database file.

.deciduous/config.toml — Configuration

Controls branch detection, hook behavior, and other project-level settings. The defaults work for most projects. The main thing it configures is which branches count as "main" branches (for grouping and filtering decisions by branch).

.claude/commands/ — Slash Commands

Nine slash commands that integrate directly into Claude Code's command system. These give your AI assistant specific workflows it can invoke: /recover to restore context from the graph, /work to start a logged work session, /decision-graph to reconstruct history from git, and more. You will see these in action throughout the rest of this tutorial.

.claude/skills/ — Contextual Skills

Three skill definitions that teach your AI assistant higher-level strategies:

  • pulse — map the current design of a system as decisions
  • narratives — understand how a system evolved over time
  • archaeology — transform evolution stories into a queryable graph

CLAUDE.md — Behavioral Instructions

This is the most important file. CLAUDE.md contains the behavioral contract that teaches your AI assistant the decision graph workflow: when to log, what to log, how to connect nodes, and when to capture verbatim prompts. It is the file that makes the entire system work automatically. Without it, deciduous is just a CLI tool. With it, deciduous becomes an integrated part of how your AI assistant thinks and works.

docs/ — Web Viewer for GitHub Pages

A static HTML viewer that can be deployed to GitHub Pages. After running deciduous sync to export your graph data, push to GitHub and enable Pages on the /docs folder. Your decision graph becomes a live, browsable website.

Keeping Up to Date

As deciduous evolves, the integration files (slash commands, skills, CLAUDE.md instructions) get updated with new capabilities. Two commands manage this:

Checking for Updates
deciduous check-update Update available! Integration files are out of date. Run 'deciduous update' to update.

When an update is available:

Applying Updates
deciduous update Updated .claude/commands/ (9 slash commands) Updated .claude/skills/ (3 skills) Updated CLAUDE.md (deciduous section) Done! Integration files are now at v0.13.2.
Your custom content is preserved

deciduous update only modifies the deciduous-managed section of CLAUDE.md, which lives between <!-- deciduous:start --> and <!-- deciduous:end --> markers. Any content you have added above or below those markers is left untouched. Your project-specific instructions, architecture notes, and custom rules are safe.

What About .gitignore?

Deciduous automatically adds the database file to your .gitignore during init:

# Added by deciduous init
.deciduous/deciduous.db
.deciduous/documents/

The database and attached documents stay local. Everything else—config, slash commands, skills, CLAUDE.md, and the docs viewer—is meant to be committed and shared with your team.
