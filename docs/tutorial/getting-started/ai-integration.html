What Your AI Assistant Gets

When you run deciduous init, your AI assistant gains a complete decision-tracking workflow. Here is what it learns.

The files created during initialization are not just configuration. They form a layered instruction set that teaches your AI assistant when to log decisions, what to log, and how to connect everything into a coherent graph. Let's look at each layer.

CLAUDE.md — The Behavioral Contract

CLAUDE.md is read by Claude Code at the start of every session. The deciduous section teaches it a specific set of behavioral rules for decision tracking. The two most important rules are:

"Log BEFORE you code, not after."

Before implementing anything, the assistant creates a goal node capturing what it is about to do and why. This ensures decisions are recorded while the reasoning is fresh, not reconstructed after the fact when details have been lost.

"Connect immediately — link every node to its parent."

Every node in the graph must be connected to its parent as soon as it is created. Orphaned nodes without connections lose their context. The graph's value is in its edges, not just its nodes.

Beyond these core rules, CLAUDE.md defines a set of behavioral triggers. When the assistant encounters one of these situations, it knows to create the corresponding node type:

Trigger Node Type Example
User asks for a new feature goal "Add dark mode support"
Exploring possible approaches option "Use CSS variables for theming"
Choosing between approaches decision "Choose theming strategy"
About to write or edit code action "Implementing CSS variable system"
Something worked or failed outcome "Dark mode renders correctly"
Noticed something interesting observation "Existing styles use hardcoded colors"

The assistant also learns the canonical flow through the graph: goals lead to options, options lead to decisions, decisions lead to actions, and actions lead to outcomes. This structure ensures the graph is consistent and navigable regardless of which session created it.

Slash Commands

The slash commands give your AI assistant specific entry points for common workflows. You invoke them by typing the command name in your Claude Code session, and the assistant follows the instructions defined in each command file.

Command Purpose
/recover Recover context from the decision graph at session start. Reads existing nodes, edges, and recent commands to rebuild understanding of the project state.
/work Start a work transaction. Creates a goal node before any implementation begins, ensuring the "log before you code" rule is followed.
/decision Full decision graph management. Add nodes, create links, update statuses, and query the graph.
/decision-graph Build a decision graph from existing git history. Analyzes commits, PRs, and patterns to reconstruct past decisions.
/build-test Build the project and run the test suite. Used to verify changes before committing.
/serve-ui Start the decision graph web viewer on a local port for interactive exploration.
/sync-graph Export the decision graph to JSON and update the GitHub Pages viewer.
/sync Multi-user sync. Pull teammate events, rebuild the local database, and push your own events.
/document Generate comprehensive documentation for a file or directory in the project.

Skills

Skills are higher-level than slash commands. Where a slash command is a specific action ("create a node", "start the viewer"), a skill is a strategy for approaching a category of work.

/pulse — Map Current Design

Take the pulse of a system as it exists today. The assistant examines the codebase and maps the current design as a set of decisions: what patterns are in use, what libraries were chosen, what architectural boundaries exist. This is "Now mode" — understanding the present without worrying about how it got this way.

/narratives — Understand Evolution

Look at the current system and ask "how did this get this way?" The assistant identifies evolution stories: the database was originally MongoDB but migrated to PostgreSQL, the auth system started with sessions and switched to JWTs, the frontend was rewritten from jQuery to React. These narratives are tracked in .deciduous/narratives.md.

/archaeology — Transform into Queryable Graph

Take the narratives identified by /narratives and structure them as decision graph nodes with proper connections. Each narrative becomes a chain of goals, options, decisions, and outcomes. Pivots — where the team changed direction — become revisit nodes that connect old approaches to new ones.

The Key Point

You do not need to memorize any deciduous CLI commands.

Your AI assistant reads CLAUDE.md, understands the workflow, and runs the right commands at the right time. You say "add rate limiting to the API" and the assistant handles the goal creation, option exploration, decision logging, and commit linking automatically. The rest of this tutorial shows you what happens during those sessions so you understand the system — but in practice, the assistant drives it.
