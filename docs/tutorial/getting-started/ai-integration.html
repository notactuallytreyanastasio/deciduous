What Your AI Assistant Gets

Three layers: a CLAUDE.md section it reads at the start of every session, nine slash commands and three skills it can invoke, and two MCP servers whose tool descriptions carry the same rules. None of it blocks the agent; since 1.0.3 nothing deciduous installs can refuse a tool call.

CLAUDE.md: the Behavioural Contract

The section between <!-- deciduous:start --> and <!-- deciduous:end --> opens with the rule everything else serves:

"THIS IS MANDATORY. Log decisions IN REAL-TIME, not retroactively."

BEFORE you do something, log what you are about to do. AFTER it succeeds or fails, log the outcome. CONNECT immediately: link every node to its parent. AUDIT regularly for missing connections.

Then the node flow rule, with its two prohibitions stated outright: goals do not lead directly to decisions (there must be options first), and options do not come after decisions. The MCP form of "connect immediately" is spelled out too: add_node with parent_id creates and links in one call, and an add_edge sent in the same batch as the add_node whose id it needs is refused, because that id does not exist yet.

The section is as specific about what not to log: reading the codebase, planning, running tests to check status, checking git. "If a node describes something the user would put on a project timeline or in a PR description, log it. If it describes your internal process of reading and thinking, don't." It also carries the git staging rule (name files, never git add -A), the verbatim-prompt rule, the message board for parallel agents, and a paragraph on the transcript import.

There are two versions of the section. A project with a [remote] gets the server-aware one: it says the graph lives on the server, .deciduous/deciduous.db is a cache, there is no graph.json to commit, and the session-start checklist is deciduous remote status rather than deciduous sync. A project without one gets the git-model text. update picks the right one for the project.

Skills

/pulse maps the current design as decisions: what is true now, as goals with their options. /narratives asks how the system got that way and writes the evolution stories to .deciduous/narratives.md. /archaeology turns those stories into nodes, with each pivot a revisit. Now mode and History mode; most projects use both.

The MCP Tools

In a project connected to the server, the agent does not run deciduous add. It calls tools on the shared server over HTTP, which Claude Code was registered with during init. There are 21: add_node, add_edge, update_node, delete_node, delete_edge, show_node, query_nodes, ask_graph, get_graph, get_ancestors, get_descendants, find_orphans, log_decision, log_observation, capture_conversation_turn, close_thread, consolidation_report, check_activity, list_workspaces, post_message and read_messages. Their descriptions and their replies carry the logging rules, which is what replaced the blocking hook: capture_conversation_turn writes a step's goal, observations, decision, action and outcome together, all or nothing; a tool refuses an unknown argument and names the one it has; check_activity says who else has been writing where.

deciduous mcp is the other server: local, over stdin/stdout, against the local database, for any MCP client ({"command": "deciduous", "args": ["mcp"]}). It has 34 tools, among them add_node, link_nodes, search_nodes, trace_chain, get_pulse, attach_document, tag_node, generate_writeup, export_dot, and the board's post_message and read_messages.

Hooks

Two, and neither blocks. version-check.sh runs before Bash calls and checks crates.io at most once a day. board-mentions.sh runs at session start and on each prompt and prints the messages addressed to this session's label (DECIDUOUS_AGENT_LABEL) that it has not answered; without a label it exits at once. Up to 1.0.2 there was a hook that denied the agent's next tool call until it wrote to the graph. It could leave a session unable to do anything, and 1.0.3 removed it; Hooks has the reasons.

You do not have to memorise any of this

The assistant reads the section, has the tools, and logs. You say "add rate limiting to the API" and get a goal with your words on it, options, a decision, actions linked to commits, outcomes. The rest of the tutorial shows what that looks like so you can read the graph it leaves behind.
