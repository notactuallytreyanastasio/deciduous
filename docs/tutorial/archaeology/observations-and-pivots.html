Tracking What Went Wrong

The valuable half of a decision graph is the half that failed. Observations record the facts that piled up; a revisit records the moment they forced a change of direction.

Observations

As Claude reads snowflex's history it finds ODBC problems scattered across commits and attaches each to the outcome it undermined:

Observations found during archaeology
deciduous add observation "Snowflake ODBC sessions expire after 4 hours idle" --date 2020-01-15 Warning: Observations should have both a title and a description (-d "..."). Use the title for a short summary and -d for the full detail. Created node 7 (type: observation, title: Snowflake ODBC sessions expire after 4 hours idle) [branch: main] [date: 2020-01-15T00:00:00-05:00] deciduous link 6 7 -r "found in production" Created edge 7 (6 -> 7 via leads_to) deciduous add observation "Snowflake returns UTF-16 that corrupts query results" --date 2020-06-10 Created node 8 (type: observation, title: Snowflake returns UTF-16 that corrupts query results) [branch: main] [date: 2020-06-10T00:00:00-04:00] deciduous link 6 8 -r "found in production" Created edge 8 (6 -> 8 via leads_to)

The warning is worth heeding. An observation's title is the one-line summary; -d is where the detail goes (which commit, what the error said, who hit it). The binary creates the node either way.

The Revisit Node

[outcome #6] → [observation #9] → [revisit #10] → [decision #11]

The revisit's title is generated from the superseded node ("Reconsidering: Working single-connection ODBC wrapper"); the two edges it sits between carry the rationales "Forced rethinking" and "New direction"; the observation's edge from #6 carries the -r reason. The old outcome is marked superseded and stays in the graph. deciduous nodes shows it; deciduous narratives pivots finds it by the revisit.

pivot has no --date

archaeology pivot stamps its three nodes with today's date. In the timeline on the next pages, nodes 9, 10 and 11 sit at 2026-10-24 between history dated 2021. The nodes created by hand around them carry --date; the pivot's do not, and there is no flag to give them one in 1.1.0. Use add and link by hand (observation, revisit, decision, three links, status <old> superseded) when the dates matter.

StatusMeaningIn snowflex
pendingNot yet resolved. The default for every node the CLI creates.Most of the graph until someone sets otherwise
activeCurrent truthThe HTTP transport option (#12), once you say so
completedDoneThe v1.0 rewrite action (#14)
rejectedConsidered, not chosenDirect HTTP client (#13)
supersededReplaced by a newer approachThe ODBC outcome (#6), set by the pivot
abandonedStarted, given upNothing in this graph

deciduous status --help lists only the first four; the binary accepts all six, as the error message above shows. archaeology supersede <id> --cascade marks a node and all its descendants superseded at once; --dry-run prints what it would touch.
