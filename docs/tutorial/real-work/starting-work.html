Starting Work on an Issue

Archaeology looked backward. Now Claude logs before it codes, and the first thing it logs is your request, word for word.

The /work Command

/work creates the goal with the verbatim prompt before anything else happens. Issue #93 asks for CI pipelines for snowflex:

That Warning

The binary warned that a 130-character prompt "looks like a summary". It was right to check: a goal's prompt is the one place the user's own words are kept, and /recover reads it to find out what was actually asked. Here the issue request really was two sentences, so the warning is noise; when Claude paraphrases a long request into one line, it is the point. The node is created either way.

Two ways to attach a prompt
# one line deciduous add goal "Fix login bug" -c 90 -p "The login page crashes on Safari" # several lines: a heredoc on stdin deciduous add goal "Add CI pipelines" -c 90 --prompt-stdin << 'EOF' ...the user's message, unchanged... EOF # add or replace later deciduous prompt 16 "..."

Only root goals and real changes of direction get prompts. Options, decisions and actions inherit their context through the edges back to the goal.

What the Agent Actually Calls

In a project connected to the server, the session above is MCP calls, not shell: add_node with node_type: "goal" and the prompt, then add_node for each option with parent_id set to the goal, then the decision with parent_id the chosen option and edge_type: "chosen". Or one capture_conversation_turn carrying the whole step. Every write passes workspace and branch. The graph that results is the one deciduous nodes prints.

The Node Flow Rule

StepNodeIssue #93
What are we trying to do?goal#16 Add CI pipelines for snowflex
What approaches exist?option#17 separate files / #18 one workflow
Which do we take?decision#19 Use separate workflow files
Build itactionnext page
What resulted?outcomenext page

Options come before the decision, never after it, and a goal does not lead straight to a decision. The edge from the chosen option into the decision is the one link would refuse to reverse, as the archaeology section showed.

Forward logging and archaeology make the same graph

Same types, same edges, same flow. The difference is --date and --commit <old hash> on the archaeology side; forward logging takes the current time and --commit HEAD.
