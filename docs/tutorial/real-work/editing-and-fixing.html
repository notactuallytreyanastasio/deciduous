CLI Reference

Editing and Fixing the Graph

Links point the wrong way, a node is a duplicate, a prompt was a paraphrase. The CLI fixes edges, statuses, prompts and whole nodes. It does not retitle a node; that is worth knowing before you need it.

Ask Claude to clean up

Claude can see the whole graph and reason about what should connect to what. "Clean up the decision graph before we export" is a reasonable request, and pulse gives it a checklist. Everything below is what it runs.

Removing a Wrong Edge

A shortcut from goal #16 straight to decision #19 skips the option layer and misrepresents how the decision was reached:

$ deciduous edges
ID    FROM   TO     TYPE         RATIONALE
----------------------------------------------------------------------
...
18    17     19     chosen       clearer separation, easier for contributors
19    19     18     rejected     one file hides which job does what
20    19     20     leads_to     implementation
21    20     21     leads_to     implementation succeeded
22    16     19     leads_to     shortcut

$ deciduous unlink 16 19
Removed edge (16 -> 19, leads_to)

When two nodes are joined by more than one edge type, unlink -t <type> says which to remove.

Deleting a Node

$ deciduous delete 22 --dry-run
Dry run: Would delete node 22 (Separate worklfow files (duplicate)) with 0 edge(s)
$ deciduous delete 22
Deleted node 22 (Separate worklfow files (duplicate)) and 0 edge(s)

$ deciduous delete 19 --dry-run
Dry run: Would delete node 19 (Use separate workflow files: clearer separation, easier for contributors) with 3 edge(s)
Delete takes the edges with it

Deleting #19 would remove its three edges and leave #17, #18 and #20 disconnected. --dry-run first, and re-link what remains if you delete a node in the middle of a chain. With a server, a delete is an operation like any other and reaches the server; it is not undone by a pull.

Fixing a Prompt

$ deciduous prompt 16 "Add CI/CD pipelines for snowflex. GitHub Actions workflows for unit tests and integration tests, with caching and an OTP/Elixir matrix. Issue #93."
Warning: Prompt is only 146 chars. This looks like a summary, not a full prompt.
         Capture the verbatim user message for better context recovery.
Updated node 16 prompt (146 chars)

$ cat issue-93.md | deciduous prompt 16

The warning fires below a length threshold; a short real prompt gets it too. Omit the text to read from stdin.

Statuses

$ deciduous status 20 completed
Updated node 20 status to 'completed'
$ deciduous status 18 rejected
Updated node 18 status to 'rejected'
$ deciduous status 16 completed
Updated node 16 status to 'completed'

Six statuses: pending (the default), active, completed, rejected, superseded, abandoned.

Retitling a Node

There is no deciduous edit in 1.1.0. A title or description typo is fixed one of two ways: through the shared server's update_node MCP tool, which Claude has in a connected project, or by adding a corrected node, moving the edges (link the new, unlink the old) and deleting the original. The local deciduous mcp server has update_status and update_prompt, not a title update. If a typo is in an option title nobody will search for, leaving it is also an answer.
