Attaching Documents to Nodes

The issue body, a screenshot, a diagram: attach them to the node they informed, and they stay with the decision when the issue is edited or the screenshot is lost.

Attaching the Issue

Claude Code — attaching issue #93
❚❚
Animation paused
Claude
gh issue view 93 --json body -q .body > issue-93.md
Claude
deciduous doc attach 16 issue-93.md -d "GitHub issue #93: Add CI pipelines"
Attached document 1 to node 16 (issue-93.md)
Description: GitHub issue #93: Add CI pipelines
Claude
The issue as it read today is on goal #16. If it is edited later, the version that drove this work is still here.

The file is copied to .deciduous/documents/ under its own name plus the first eight characters of its sha256, so the original can go and the same content attached twice is stored once. doc list <node> narrows to one node; --json on list and show gives data.

Documents do not travel on their own

.deciduous/documents/ is under the .deciduous/* ignore rule, so it is not committed. With a graph server, attaching a document does not send it either: documents are not operations in the write log. deciduous remote push --seed sends the ones attached since the last seed, bytes included, and the server stores them by sha256 across workspaces. Without a server, a document exists on the machine that attached it.

Detach and Garbage-Collect

$ deciduous doc detach 1
Detached document 1
$ deciduous doc list --include-detached
1 documents:
ID    NODE     FILENAME                  TYPE       SIZE     DESCRIPTION
--------------------------------------------------------------------------------
1     16       issue-93.md               text/m...  133B     GitHub issue #93: Add CI pi...
$ deciduous doc gc --dry-run
1 orphaned files:
  /Users/alice/code/snowflex/.deciduous/documents/issue-93.md.9fe06eb0
(dry run - no files deleted)

detach is a soft delete: the record stays (visible with --include-detached) and the file stays on disk until doc gc removes files no active record points at. There is no "reattach"; attach the file again and you get a new document id.

Descriptions

-d at attach time, or doc describe <id> "text" later (omit the text to read it from stdin). --ai-describe on attach and --ai on describe shell out to the claude CLI to write one; this tutorial did not run them. doc open <id> opens the stored file in the default application.

CommandDoes
doc attach <node> <file> [-d text | --ai-describe]Copy the file into .deciduous/documents/ and attach it
doc list [node] [--include-detached] [--json]List documents
doc show <id> [--json]Details including hash and storage path
doc describe <id> [text] [--ai]Set the description
doc open <id>Open the file
doc detach <id>Soft-delete the attachment
doc gc [--dry-run]Delete files no active record references
Attach the version that informed the decision

Issues get edited, screenshots get overwritten, specs move. Attach at the start of the work, before the thing can change.
