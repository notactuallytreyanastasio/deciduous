The Implementation Session

Claude writes the code, logs the actions, commits, and links everything back to the graph. You watch and steer.

With goal #57, options #58/#59, and decision #60 already recorded, Claude now moves into the implementation phase. This is where action and outcome nodes appear—the bottom half of the decision flow.

Logging the Action

The --commit HEAD Pattern

After every git commit, Claude uses --commit HEAD on the next node (usually an outcome). This captures the commit hash and links it to the graph. The web viewer shows the commit message, author, and date alongside the node details.

Linking commits to the graph
# The pattern: commit, then log the outcome with --commit HEAD git commit -m "ci: add unit test workflow" deciduous add outcome "Unit test CI working" -c 90 --commit HEAD # --commit HEAD resolves to the current commit hash # The web viewer displays this as a clickable commit link

The -f flag on action nodes serves a different purpose: it records which files Claude intends to modify, before the work begins. Together, -f on actions and --commit on outcomes create a complete audit trail: what was planned, what was changed, and the exact commit that contains those changes.

Recovering Mid-Session

Long sessions hit context limits. When Claude's context window fills up, it compacts—and loses the details of what it was working on. The /recover skill rebuilds context from the decision graph.

Claude Code — After context compaction
❚❚
Animation paused
You
/recover
Claude
deciduous nodes --status pending,active
ID TYPE STATUS TITLE
57 goal active Add CI pipelines for snowflex
60 decision active Use separate workflow files...
61 action active Implement unit test CI workflow
62 outcome active Unit test CI workflow working...
Claude
deciduous edges
FROM TO TYPE RATIONALE
57 58 leads_to possible approach
57 59 leads_to possible approach
58 60 leads_to chosen
60 61 leads_to implementation
61 62 leads_to implementation succeeded
Claude
Context recovered. I'm working on issue #93: CI pipelines for snowflex. The unit test workflow (node 61) is complete with outcome #62 linked to commit a1b2c3d. The integration test workflow still needs to be implemented. Ready to continue.

The graph told Claude everything it needed: the goal, the chosen approach, what's been done, and what remains. No re-reading of issue bodies or commit logs. The verbatim prompt on goal #57 gives Claude the original user request, and the edges trace the full reasoning chain.

Recovery is why connections matter

An orphaned node is useless for recovery. Claude can read the node title, but without edges it cannot tell what spawned the node, what it relates to, or what should happen next. This is why the CLAUDE.md instructions insist on linking every node immediately after creation: the edges are the recovery path.

Don't let compaction degrade your session

If you notice Claude's responses becoming less contextual — forgetting what it was working on, asking questions it already answered — compaction is happening. Don't fight it. Instead, use /clear to wipe the degraded context, then immediately run /recover with a brief note about what you were doing:

> /clear

> /recover — I was implementing the integration test workflow, node 61 is complete

This gives Claude a clean slate with fresh context recovered from the graph. It's faster and produces better results than letting a compacted session stumble forward.
