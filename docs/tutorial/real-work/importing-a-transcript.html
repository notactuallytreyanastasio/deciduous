Importing a Transcript

An agent that logs its own decisions can forget to. The transcript cannot. Claude Code writes every session to a JSONL file; since 1.1.0 deciduous transcript import derives the graph from it, and every node it makes says what it is backed by.

The Session Had a Transcript All Along

Every prompt you typed, every file the agent edited, every command it ran and what came back is in ~/.claude/projects/<slug>/<session-id>.jsonl, the slug being the project's absolute path with every character outside [A-Za-z0-9] replaced by -. transcript list shows this project's sessions and whether each is already in the graph:

$ deciduous transcript list
/Users/alice/.claude/projects/-Users-alice-code-snowflex
new      7c3e9a10    2 prompts  2026-10-24  Add CI pipelines for snowflex

The scratch project for this tutorial has no directory under ~/.claude/projects/, so list there fails with No such file or directory; the runs below pass --dir and a path instead. The transcript is the issue #93 session from the previous pages, written by hand in Claude Code's format: one prompt, a Read of mix.exs, a Write of the workflow and an Edit of mix.exs, mix test, a git commit, the closing report, then a second prompt answered in prose.

One session is one tree. The first prompt is the root goal (#23), titled with the name Claude Code gave the session. Each later prompt is a goal under it (#28, edge rationale "prompt 2 of the session"). Under each goal sit its actions, and under each action the command outcomes that followed it; the closing report hangs off the goal beside the proven outcomes, not under one of them.

Notice #16 and #23 are both "Add CI pipelines for snowflex". #16 is the goal the agent logged itself; #23 is the one derived from the transcript. The import does not merge them: it skips the mcp__deciduous__* calls and deciduous add commands it finds in the transcript (those nodes are already there) but has no way to know that #16 is the same intent. Joining the two trees is an edge you add.

Three things on this one node. Description is what the assistant said just before the edit run: the stated intent next to the proof of what was done. Consulted is every file the agent Read since the previous action: the evidence trail a filesystem watcher would give, without one. Files carry hashes taken at import time, as git blob ids (git:<sha1>, the id git log --find-object takes; sha256: outside a repository), so you can find the commit that holds exactly that content. --no-hash skips the hashing when the files may be half-written.

Proven means the transcript recorded the thing happening: a tool call and its result, or your own words. Inferred means the assistant said so. The two sit side by side on purpose. When a closing report says "all tests pass" and the cargo test outcome beside it says 12 passed, 1 failed, the second is the one to believe, and the graph says which is which. The same distinction applies to #29: a turn that only answered produces an observation, inferred.

Importing Twice Changes Nothing

$ deciduous transcript import ~/transcripts/7c3e9a10-5b2d-4f61-9e8a-2d4c6b8f0a93.jsonl
Imported Add CI pipelines for snowflex (7c3e9a10, 2 prompts)
  goals 0 · actions 0 · outcomes 0 proven, 0 inferred · observations 0 · edges 0
  7 already present · 2 files hashed
  root goal #23: deciduous show 23

Change ids are derived from the session id and each entry's uuid (look at #23's change id, 9c05bd22-83e5-87c4-...: not a random UUID), so a second import finds everything present, and two people importing the same transcript produce the same nodes, which deciduous sync then merges as one. --json prints the report as data, one object per transcript, including what was skipped (subagent calls, deciduous writes, other tools) and unreadable_lines.

What Is Not Derived

  • Decisions and options. Whether one approach was chosen over another is a judgement about prose, not a fact in a tool result. The material is there (each action's description is what the assistant said it was about to do); the pass that writes option and decision nodes belongs to an agent reading the imported graph, with capture_conversation_turn as its pen. This is why #16 to #21, logged live, have a decision and the imported tree does not.
  • Subagent work. An Agent call is counted and skipped; its transcript under <session>/subagents/ is not imported as a subtree yet.
  • Reads, searches, ordinary commands. ls, grep, git status leave no node; Read calls survive only as the next action's consulted list.
  • Other assistants' transcripts. Only Claude Code's format is read. A file with no user prompt in it is refused by name: agent-only.jsonl: no user prompt in this transcript (a subagent file, or a session that never got a message); nothing to derive.
  • A session id outside the project's directory. import 7c3e9a10 looks only under ~/.claude/projects/<this project>/; in the scratch project that was not a file, and no transcript directory to look it up in. Pass the path.

Running It at the End of Every Session

A Claude Code SessionEnd hook receives the transcript path on stdin. With this in .claude/settings.json, the agent never has to log anything for the session to be in the graph:

{
  "hooks": {
    "SessionEnd": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "jq -r .transcript_path | xargs deciduous transcript import --no-hash >/dev/null 2>&1 || true"
          }
        ]
      }
    ]
  }
}

--no-hash because the session may have ended mid-edit and a hash of a half-written file is not worth keeping; hash on a later import, or leave it on and accept that. /recover does the other half: at the start of a session it runs transcript list and imports anything marked new, so a session that logged little still arrives in the graph before anyone reads it.

The numbers that motivated this

On a three-week session that had logged nine nodes through MCP while it ran, the import found 119 edits and commits, 67 build and test results, and 68 verbatim prompts. docs/transcripts.md in the repository is the canonical description of the feature.
