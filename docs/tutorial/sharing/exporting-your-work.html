Exporting Your Work

With a server the graph is already shared; the exports that remain are for git, for pictures, for PR bodies and for backups. One export that older docs describe, sync writing docs/graph-data.json, stopped in 1.0.5.

sync: the Git-Tracked Graph

$ deciduous sync
Synced /Users/alice/code/snowflex/.deciduous/graph.json (22 nodes, 22 edges, 2 themes, 3 tags on disk)
  Database and records already agree
$ deciduous sync --check
Checked /Users/alice/code/snowflex/.deciduous/graph.json (22 nodes, 22 edges, 2 themes, 3 tags on disk)
  Database and records already agree

sync reconciles .deciduous/graph.json with the local database in both directions: run it after git pull to receive teammates' records and before git push to write yours out. The file holds nodes, edges, themes and tags keyed by change id; it is one file because 0.17's directory of per-record files cost 2,781 files and 11 MB for a 1 MB graph, and a merge driver (registered by init) merges concurrent changes record by record. Since 1.0.11 the database follows the file across branch checkouts, so a node added on one branch no longer appears on every branch. A pre-0.17 JSONL event log is imported and removed on the first sync.

In a project with a [remote], sync is not the step. The server-aware CLAUDE.md says so directly: "There is no .deciduous/graph.json to commit or merge." The equivalents are:

$ deciduous remote status    # what differs between this copy and the server; exit 1 if anything
$ deciduous remote pull      # send what is waiting, then refresh the local cache from the server
$ deciduous remote push      # send writes still waiting in .deciduous/remote-log.jsonl

Every CLI write is appended to .deciduous/remote-log.jsonl as an operation naming only what changed and what each field held before, and sent before the command exits; a write made while the server is down waits there for the next write or remote push. push --seed sends history written before the project had a remote (and the documents attached since the last seed). In the scratch project, with no remote, all three print no remote configured for this project.

-o file writes to a file, --rankdir LR (or BT, RL) changes direction, --png renders with Graphviz, --auto does the branch-named files the previous page used. deciduous writeup takes the same --nodes/--roots selection and -o PR-WRITEUP.md; attaching that file to the goal with doc attach keeps the PR text with the decision it describes.

backup

$ deciduous backup
Created backup: deciduous_backup_20261024_125040.db (290816 bytes)

A copy of the SQLite database, written to the current directory (not to .deciduous/backups/ as earlier docs said); -o names the path. Since it lands next to your code, name it somewhere git ignores, or you will see it in git status as this tutorial's scratch run did.

Never delete the database

With a server, .deciduous/deciduous.db is a cache, and the only copy of writes that have not been sent yet: deciduous remote status lists them. Without a server it is the graph. Back it up before anything you are unsure about.

What About GitHub Pages?

Until 1.0.5, init wrote a docs/ viewer and sync exported docs/graph-data.json and docs/git-history.json for it. Neither happens now: the graph moved to the server and deciduous serve is how you look at it. The live demo on this site is an export of deciduous's own graph, 1,465 nodes and 1,313 edges on 2026-10-24; there is no command in 1.1.0 that produces that page for another project.
