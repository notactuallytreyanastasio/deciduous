How to Read This Tutorial

One Continuous Story

Every section works on the same project, snowflex. The graph you build in Reconstructing History is the one you extend in Live Development and share in Sharing. Node ids carry across pages: the snowflex history is nodes 1 to 15, the CI work is 16 to 21, the transcript import adds 23 to 29.

Claude Drives, You Steer

Most sessions here are Claude Code sessions in which Claude runs deciduous. You say what you want; it logs. You do not have to know a single deciduous command to use the tool, and your assistant already knows them all. The commands are shown so you understand what is being recorded, and so you can run them yourself when you want to.

One thing to know before the sessions: when a project is connected to the graph server, Claude writes through MCP tools (add_node with a parent_id, capture_conversation_turn for a whole step) rather than through the shell. This tutorial shows the CLI form because its output is readable in a terminal, and because the CLI is what you type yourself. The nodes that result are the same.

What the Output Is

Every deciduous command in this tutorial was run against the 1.1.0 release binary on 2026-10-24, in a scratch repository standing in for snowflex, and the output shown is what it printed. Where a command did not do what the previous version of this tutorial claimed, the page says so. Claude's prose in the sessions is edited for length; the commands and their output are not.

Claude Code Session
> /decision-graph I'll read the whole log before building anything. git log --oneline --reverse | wc -l 130

The > line is what you type. Highlighted lines are commands Claude ran; dimmer lines are their output; plain text is Claude talking. Animated sessions (with Pause and Replay buttons) replay the same thing step by step.

Tutorial Structure

  1. Getting Started: install, deciduous init, the question it asks about where the graph lives, and the files your assistant is handed.
  2. Reconstructing History: /decision-graph on snowflex. Backdated nodes, observations, the ODBC-to-HTTP pivot via archaeology pivot, and the narrative.
  3. Live Development: /work on issue #93, attaching the issue, linking the commit, recovering after compaction, then importing the session's transcript and editing the graph.
  4. Sharing: the PR writeup and image, what teammates have to do, and the exports.
  5. Advanced: themes and tags, the hooks that exist in 1.1.0 (none of them block), and OpenCode and Windsurf.
  6. CLI Reference: every command and flag, from --help.

Conventions

$ deciduous nodes -t goal
4 nodes:
ID    CHANGE    TYPE         STATUS     TITLE
------------------------------------------------------------------------------
1     58dbfd59  goal         pending    Create an Elixir library for querying Snowflake

Lines without $ are output. The CHANGE column is the first eight characters of the node's change id, which is the same on every machine while the integer id is not.

Note

Blue boxes are background.

Warning

Yellow boxes are things that go wrong.

Tip

Green boxes are shortcuts.

Node Types

  • goal: what is being attempted ("Add CI pipelines for snowflex")
  • option: an approach considered ("Separate workflow files")
  • decision: the choice ("Use separate workflow files")
  • action: work done ("Implement unit test CI workflow")
  • outcome: what resulted ("mix test passed")
  • observation: a fact found ("ODBC sessions expire after 4 hours idle")
  • revisit: an approach reconsidered ("Reconsidering: Working single-connection ODBC wrapper")

Prerequisites

  • A terminal and git.
  • Claude Code, or OpenCode or Windsurf (see Multi-Assistant). The transcript import reads Claude Code's format only.
  • For the default setup, a PostgreSQL on localhost:5432. init tells you how to get one if nothing answers there.

No Elixir knowledge is needed; the snowflex code is never the point, the decisions are.
