Themes and Tags

Branches group nodes by when. Themes group them by what: the transport layer is a concern that runs from the 2019 ODBC option through the 2021 pivot to the HTTP rewrite.

Creating Themes

$ deciduous themes create transport-layer --color "#3b82f6" -d "Transport abstraction and protocol decisions"
Created theme 'transport-layer' (id: 1, color: #3b82f6)
$ deciduous themes create ci-infrastructure -d "CI/CD and testing infrastructure"
Created theme 'ci-infrastructure' (id: 2, color: #6b7280)
$ deciduous themes list
2 themes:
NAME                 COLOR      DESCRIPTION
------------------------------------------------------------
ci-infrastructure    #6b7280    CI/CD and testing infrastructure
transport-layer      #3b82f6    Transport abstraction and protocol decisions

Names are lower-cased and dash-separated. Without --color every theme gets the same grey, #6b7280; pick colours if the viewer is where you will use them.

Tagging Nodes

$ deciduous tag add 10 transport-layer
Tagged theme 'transport-layer' to node 10
$ deciduous tag add 11 transport-layer
Tagged theme 'transport-layer' to node 11
$ deciduous tag add 16 ci-infrastructure
Tagged theme 'ci-infrastructure' to node 16
$ deciduous tag list 10
Themes for node 10:
  transport-layer (#3b82f6)
$ deciduous nodes --theme transport-layer
2 nodes:
ID    CHANGE    TYPE         STATUS     TITLE
------------------------------------------------------------------------------
10    47546c20  revisit      pending    Reconsidering: Working single-connection ODBC wrapper
11    945c0ef6  decision     pending    Switch to Snowflake's HTTP REST API with JWT auth

A node can carry several themes. nodes --theme is the query that makes a theme useful from the terminal.

Suggestions

$ deciduous tag suggest 12
No theme suggestions found.

tag suggest [node] (all untagged nodes when the id is omitted) matches node titles against theme names and descriptions by keyword; the help text also mentions AI, but in the scratch project it found nothing for an option whose title shares no word with a theme, and made no external call. --apply writes the matches it does find as suggested tags; tag confirm <node> <theme> turns a suggested tag into a manual one. Expect to tag by hand, or have Claude do it, which is what the graph's agent is good at.

Removing

$ deciduous tag remove 11 transport-layer
Removed theme 'transport-layer' from node 11
$ deciduous themes delete ci-infrastructure
Deleted theme 'ci-infrastructure'

themes delete removes the theme and every tag that used it.

Where Themes Go, and Where They Do Not

deciduous sync carries themes and tags in .deciduous/graph.json (the sync output on the previous page counts "2 themes, 3 tags on disk"), so in the git model they travel. They do not go to the graph server: the SQLite themes/node_themes tables and the matching PostgreSQL columns both exist, but nothing in 1.1.0 carries the assignments across, and deciduous graph does not include them. On a project with a server, a theme is local to the machine that made it.

In the web viewer (deciduous serve) themed nodes take the theme's colour and the filter panel can show one theme at a time.

Two orthogonal slices

nodes -b ci-pipelines is when. nodes --theme transport-layer is what. Both are cheap to apply; themes are the one you have to put there yourself.
