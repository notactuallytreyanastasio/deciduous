Hooks

Deciduous installs two hooks and neither can stop the agent. The one that could, a hook that denied the next tool call until the graph was written to, was removed in 1.0.3. This page is what remains, why, and how to add your own.

Why There Are No Logging Hooks

Up to 1.0.2, init installed a PreToolUse hook that counted an agent's actions between graph writes and denied the next tool call after ten, or straight after an unlogged commit. In practice it stopped sessions cold. A PreToolUse for one call runs before the PostToolUse of the graph write sent beside it, so a write made in the same batch as the next action did not count. A session whose settings changed underneath it kept counting with no way to reset. And DECIDUOUS_LOG_LOOP=off typed into the session never reached the hook, because hook processes inherit the environment Claude Code started with. A rule that blocks work has to be one the agent can satisfy every time, and this one could not.

1.0.3 removed it. deciduous update deletes the hook scripts deciduous wrote (a user's own are kept) and takes every deciduous log-loop entry out of .claude/settings.json. Logging is encouraged instead by what the agent reads anyway: the CLAUDE.md section, and the MCP tools' descriptions and replies. Since 1.1.0 the transcript import is the backstop for what the agent did not log.

What init Installs

$ cat .claude/settings.json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "\"$CLAUDE_PROJECT_DIR/.claude/hooks/version-check.sh\"" }
        ]
      }
    ],
    "SessionStart": [
      {
        "hooks": [
          { "type": "command", "command": "\"$CLAUDE_PROJECT_DIR/.claude/hooks/board-mentions.sh\" start", "timeout": 10 }
        ]
      }
    ],
    "UserPromptSubmit": [
      {
        "hooks": [
          { "type": "command", "command": "\"$CLAUDE_PROJECT_DIR/.claude/hooks/board-mentions.sh\" prompt", "timeout": 10 }
        ]
      }
    ]
  }
}
HookWhenWhat
version-check.shBefore each Bash callAsks crates.io for the latest version at most once per 24 hours, 3-second timeout. A patch update gets one quiet line; a minor or major update a banner. Always exits 0.
board-mentions.shSession start, and each promptIf DECIDUOUS_AGENT_LABEL is set, prints the board messages addressed to that label and not yet answered (deciduous board read --unanswered $label); on prompts, only what arrived since it last showed any. Without a label it exits immediately. Always exits 0.

deciduous integration lists what is installed; in the scratch project it showed both hooks, nine commands, three skills, three agents and settings.json.

Your Own Hooks: deciduous hooks install

deciduous hooks installs the hooks a project lists under [hooks] in .deciduous/config.toml. The script is inline or in a file relative to .deciduous/; the matcher is a Claude Code tool-name pattern. A reminder after commits, for example:

[hooks]
enabled = true

[[hooks.post_tool_use]]
name = "remind-to-sync"
description = "After a git commit, remind the session to run deciduous sync"
matcher = "Bash"
enabled = true
script = '''#!/bin/bash
# Reads the tool call from stdin; prints a reminder after a git commit. Never blocks.
input=$(cat)
case "$input" in *"git commit"*) echo "Committed. Run: deciduous sync" ;; esac
exit 0
'''

$ deciduous hooks install
Installing Claude Code hooks...
   Installed .claude/hooks/remind-to-sync.sh
   Generated .claude/settings.json

Hooks installed from .deciduous/config.toml.

$ deciduous hooks status
Hook Configuration
   Enabled: yes

Pre-Tool-Use Hooks (block before Edit/Write/etc):
   (none configured)

Post-Tool-Use Hooks (run after Bash/etc):
   ✓ remind-to-sync (matcher: Bash)
      After a git commit, remind the session to run deciduous sync

Installation Status:
   remind-to-sync installed
hooks install rewrites settings.json from config.toml alone

After the run above, .claude/settings.json contained only the PostToolUse entry for remind-to-sync. The version-check and board-mentions entries that init wrote were gone, though their scripts were still on disk. deciduous hooks uninstall then removed the whole .claude/hooks/ directory, those two scripts included. deciduous update afterwards recreated both scripts and put the board-mentions entries back on SessionStart and UserPromptSubmit; it did not restore the PreToolUse entry for the version check. If you use hooks install, run deciduous update after it and check settings.json.

Two hook names are refused by name: require-action-node and post-commit-reminder, the 1.0.2 logging hooks, which hooks install answers with was removed in deciduous 1.0.3; delete it from .deciduous/config.toml. The --help text for deciduous hooks still describes "pre-edit blocks, post-commit reminders"; that is the one place the old behaviour survives, and it is text.

The One Hook Worth Adding

A SessionEnd hook that imports the transcript, from Importing a Transcript. It is not a deciduous-managed hook; add it to .claude/settings.json yourself:

"SessionEnd": [
  {
    "hooks": [
      {
        "type": "command",
        "command": "jq -r .transcript_path | xargs deciduous transcript import --no-hash >/dev/null 2>&1 || true"
      }
    ]
  }
]

It cannot block anything either; || true sees to that.

Other Assistants

OpenCode gets the version check as a TypeScript plugin, .opencode/plugins/version-check.ts; the logging plugins were removed in 1.0.3 along with the Claude Code hook. Windsurf gets .windsurf/hooks.json running .windsurf/hooks/version-check.sh on pre_write_code. Neither has a board-mentions equivalent.
