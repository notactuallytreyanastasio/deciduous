Working with Multiple AI Assistants

Deciduous is not limited to Claude Code. The same decision graph works with OpenCode, Windsurf, and other AI assistants.

The decision graph is stored in a SQLite database and operated through the deciduous CLI. Any AI assistant that can run shell commands can use it. What differs is the integration layer—the instruction files that teach the assistant when and how to log decisions.

Supported Assistants

Assistant Init Flag Integration Files
Claude Code (default) CLAUDE.md, .claude/commands/, .claude/skills/
OpenCode --opencode AGENTS.md, OpenCode-compatible instructions
Windsurf --windsurf .windsurfrules, Windsurf-compatible instructions

Initializing for Different Assistants

When you run deciduous init, the default is Claude Code integration. To add support for other assistants, use the appropriate flag:

Initializing for OpenCode
deciduous init --opencode Initialized deciduous in /Users/alice/projects/snowflex Created .deciduous/ Created .deciduous/config.toml Created CLAUDE.md (decision graph workflow) Created AGENTS.md (OpenCode integration) Created .claude/commands/ (7 commands) Created .claude/skills/ (3 skills) Created docs/ (web viewer)
Initializing for Windsurf
deciduous init --windsurf Initialized deciduous in /Users/alice/projects/snowflex Created .deciduous/ Created .deciduous/config.toml Created CLAUDE.md (decision graph workflow) Created .windsurfrules (Windsurf integration) Created .claude/commands/ (7 commands) Created .claude/skills/ (3 skills) Created docs/ (web viewer)

You can pass multiple flags to set up integration for several assistants simultaneously:

Multi-assistant init
deciduous init --opencode --windsurf Initialized deciduous in /Users/alice/projects/snowflex Created .deciduous/ Created CLAUDE.md (decision graph workflow) Created AGENTS.md (OpenCode integration) Created .windsurfrules (Windsurf integration) Created .claude/commands/ (7 commands) ...

Managing OpenCode Integration

For finer control over the OpenCode integration, use the opencode subcommand:

OpenCode management
deciduous opencode install Installed OpenCode integration: Created AGENTS.md with decision graph workflow Feature parity with Claude Code integration deciduous opencode status OpenCode integration: installed AGENTS.md: up to date (v0.13.2) Last updated: 2024-01-15

To remove the OpenCode integration without affecting other assistants:

Uninstalling OpenCode
deciduous opencode uninstall Removed OpenCode integration: Deleted AGENTS.md

Same Graph, Different Assistants

The key insight is that every assistant writes to the same SQLite database. A node created by Claude Code is visible to OpenCode and vice versa. The CLI is the common interface:

Shared database
# Claude Code creates a goal deciduous add goal "Add CI pipelines for snowflex" -c 90 Created node #57: goal "Add CI pipelines for snowflex" # OpenCode picks up where Claude left off deciduous nodes --type goal 3 nodes: ID TYPE STATUS TITLE 1 goal active Create an Elixir library for querying Snowflake 41 goal active Transport layer evolution 57 goal active Add CI pipelines for snowflex # OpenCode adds an action linked to Claude's goal deciduous add action "Implement unit test CI workflow" -c 85 Created node #60: action "Implement unit test CI workflow" deciduous link 57 60 -r "Implementation"

This means you can switch between assistants mid-project without losing any decision context. The graph is the shared memory.

Updating Integration Files

When you upgrade deciduous, the integration files for all installed assistants are updated automatically:

Updating all integrations
deciduous update Updated integration files to v0.13.2: Updated CLAUDE.md (decision graph workflow section) Updated .claude/commands/ (7 commands) Updated .claude/skills/ (3 skills) Updated AGENTS.md (OpenCode integration) Skipped .windsurfrules (not installed)

The update command auto-detects which assistants are installed by checking for their integration files. It only updates files for assistants that are present.

Check before updating

Run deciduous check-update to see if your integration files are out of date without making any changes. This compares the version in .deciduous/.version with the current binary version.

Integration Parity

All assistant integrations have feature parity. The same behavioral rules—log before you code, connect every node, capture verbatim prompts—are encoded in each integration's instruction format. The decision graph workflow is identical; only the file format and location differ to match each assistant's conventions.
