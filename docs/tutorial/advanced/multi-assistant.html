Working with Multiple AI Assistants

Claude Code is the default; --opencode and --windsurf add the others. The graph is the same; what differs is which files carry the instructions and which assistant gets the MCP server registered for it.

Same Graph

Every assistant that can run a shell command can run deciduous add, and every node lands in the same database (and, with a [remote], on the same server). The OpenCode tool at .opencode/tools/deciduous.ts wraps the CLI for OpenCode's tool-calling; the Windsurf rules tell Cascade to run the CLI. A goal Claude Code created this morning is what OpenCode's /recover finds this afternoon.

What Is Claude Code Only

  • MCP registration. init's server step registers the shared server with Claude Code (claude mcp add --scope user --transport http deciduous <url>/mcp --header "Authorization: Bearer $DECIDUOUS_MCP_TOKEN"). For any other MCP client, that is the endpoint and header to configure by hand; deciduous mcp is the local stdio alternative for clients that can spawn a process.
  • Server-aware instructions. A project with a [remote] gets a CLAUDE.md section and commands written for the server model (remote status, no graph.json). The 1.0.12 changelog is explicit that OpenCode and Windsurf files have no remote-aware versions yet; their text still describes deciduous sync and graph.json.
  • The transcript import reads Claude Code's JSONL format only. Another assistant's log is not refused, it is a file with no user prompt in it, and the import says so.
  • The message-board hook exists for Claude Code only; the board itself (deciduous board) is a CLI any of them can run.

Updating

deciduous update detects .claude/, .opencode/ and .windsurf/ and updates whichever are present, with the same rule everywhere: a file deciduous wrote is replaced, a file someone else edited is kept (Markdown gets the new text appended in a marked block), and everything changed is backed up to .deciduous/update-backups/<time>/ first. OpenCode command files are generated from the Claude templates at run time, so a project's first update after 1.0.3 appended to them rather than replacing; later updates recognise them by the hash recorded when written.
