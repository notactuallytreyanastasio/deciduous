CHOSEN

The Sync Challenge

10 days

Multi-User Decisions

#882 sync multi-user

The hardest problem: how do multiple users share decisions when each has a local SQLite database? The solution was inspired by jj (Jujutsu): a dual-ID model where every node has a local id (integer) and a global change_id (UUID).

deciduous diff export creates shareable JSON patches. deciduous diff apply imports them—idempotently. Same patch applied twice produces no duplicates. The sync model was later extended with an event-log system for fully asynchronous team workflows.

One Sync Mechanism

v0.17.0

The Record Store

#1442 #1443 7c28507
observation #1443
Four overlapping sync mechanisms exist today

Patches, an event log, a checkpoint, and docs/graph-data.json: four ways for the graph to leave a machine, none of them the one everybody used. Goal #1442 replaced them with a git-native record store: .deciduous/sync/, one JSON file per node, edge, theme and tag, written by the database layer so the CLI, the MCP server and the HTTP API all published without being asked. Two people adding records touched different files, so git merged them with no conflict.

#1458 Merge driver + field-level 3-way merge
Concurrent edits of one record merge field by field through deciduous merge-record, with conflict-marker repair in deciduous sync as the fallback
7c28507 graph: migrate the decision graph to the record store

That commit is also the last time docs/graph-data.json was exported. The counts on this page come from it.

September 18, 2026

One File Again

v0.18.0

2,781 Files for a Megabyte

graph.json merge driver

The record store's design was sound and its bill was not: 2,781 files and 11 MB of directory overhead for a graph whose content is about 1 MB. git status after a sync was a wall of paths, a PR touching the graph was hundreds of files, and a rename could put a record in a file named after a different one.

0.18.0 folded the directory into one file, .deciduous/graph.json, keyed by change_id. One file means every concurrent change conflicts in git, so the merge driver stopped being a nicety and became the mechanism: it merges the two documents record by record, keeps a record only one side has, and merges a record both sides changed field by field with the ancestor as tiebreak. A graph.json that will not parse stops a sync rather than reading as an empty graph, which would have exported every local row over whatever was in the file.

September 21–22, 2026

The Shared Server

v0.19.0 → v1.0.0

Ten Agents, Twenty-Six Minutes

tetris-arena took_from

0.19.0 put every project's graph in one PostgreSQL behind an MCP endpoint over HTTP: one workspace per repository, deciduous remote to point a repository at it, the token stored outside every repository, the local database demoted to a cache. 1.0.0, the next day, is what happened when several agents wrote to it at once.

Ten Claude Code sessions in ten git worktrees of one repository, one workspace, told to read each other's code and reasoning. Twenty-six minutes later there were ten playable Tetris games, 386 nodes and 170 borrowed ideas with provenance. Zero of the arena's 471 edges crossed a branch, because nothing said a borrow was an edge: the borrow counts came from a regular expression over observation titles. 1.0.0 added the took_from edge type, check_activity with the last node on each branch, and a deciduous remote watch that quotes every write instead of counting them, because a watcher that counted had invented a convention that did not exist.

Every MCP call from a long-lived Claude Code session hung for 300 seconds. The server answered a dead session with a 200 under a freshly generated id, not the request's id, so the client could never match it.
— CHANGELOG, 1.0.0

Two fixes from the same day describe the shape of the work from here on: the event socket closed every subscriber after sixty seconds because it was upgraded with no options, and every connection paid five seconds before its first call because the server answered an unknown method as if it were a notification.

September 23–28, 2026

Eleven Releases in Six Days

v1.0.2 → v1.0.3

The Hook That Blocked Work

log-loop removed

1.0.2 installed a hook that counted an agent's actions between graph writes and denied its next tool call after ten, or after an unlogged commit. It lasted one release. A PreToolUse for one call runs before the PostToolUse of the graph write sent beside it; a session whose settings changed underneath it kept counting with no way to reset; an environment variable typed into the session never reached the hook. It stopped sessions cold.

A rule that blocks work has to be one the agent can satisfy every time, and this one could not.
— CHANGELOG, 1.0.3

1.0.3 removed it and made deciduous update stop destroying what it did not write: upgrading 86 projects on one machine had taken a script that put back 59 files. 1.0.4 replaced the hook with the MCP server's instructions on initialize, which reach every client and cannot block anything.

v1.0.5 → v1.0.9

Init Asks, Writes Become Ops, Agents Get a Board

remote setup remote-log.jsonl board

1.0.5 made init refuse to finish until the project pointed at a server that answered, and dropped the GitHub Pages export, since the graph now lived on the server. 1.0.6 made it ask where the graph should live instead of choosing Docker for you. 1.0.7 found one workspace with 502 nodes locally against 0 on the server it was configured to use, and nothing had said so; it also stopped putting every local server on port 4000, Phoenix's default, where it had squatted the dev server of the very project being logged.

1.0.8 made every CLI write an op in .deciduous/remote-log.jsonl, replayed on the server field by field, each at most once, carrying the value it replaced so a queued edit never overwrites a newer one. 1.0.9 gave agents working in parallel a message board in the same store as the graph, with @label mentions and reply_to, in place of the scratch markdown file they kept inventing.

v1.0.10 → v1.0.12

PostgreSQL on This Machine

launchd systemd ask_graph

1.0.10 rebuilt ask_graph: anchors from trigram and full-text rankings fused by reciprocal rank, routes chosen by the shape of the question, and an honest answer when the graph has nothing on the subject. Recall@10 went from 0.611 to 0.889. It was tagged and never published: three security advisories against mint made every self-contained server build refuse.

1.0.11 carried all of it, plus the change that defines the current setup: a server on this machine needs PostgreSQL, not Docker. init runs the release's self-contained server as a launchd LaunchAgent or a systemd user unit against the PostgreSQL already on localhost:5432, as the current user, database deciduous, listening on 127.0.0.1 only. The local database started following graph.json across branch switches. 1.0.12 fixed six defects a customer case study had reproduced, each of which lost or misrepresented work without saying so; the first was that update rewrote hand-written server-model instructions back to the git model.

October 24, 2026

The Transcript Is the Log

v1.1.0

Nine Nodes, or 119 Actions

5548d8f evidence

Every chapter above assumed the agent would log as it worked, and every release since 1.0.2 had tried a different way to make it: a blocking hook, server instructions, a CLAUDE.md section. 1.1.0 stops relying on it. Claude Code already writes the whole session to a JSONL transcript; deciduous transcript import reads it.

5548d8f transcript: build the graph from a Claude Code transcript, with evidence on every node

Each prompt becomes a goal with the prompt verbatim; each run of edits, or a shell command that changed files, an action naming the files; each commit an action with the hash; each build, test or lint run an outcome with its exit and summary; the assistant's closing text an outcome too. On the three-week session that built the shared server, the agent had logged nine nodes through MCP. The transcript held 119 actions, 67 command outcomes and 68 verbatim prompts.

Every derived node says what it is backed by: proven (a tool call and its result, or the user's own words) or inferred (the assistant said so). The assistant's "all tests pass" and the cargo test result sit side by side, labelled. Importing twice adds nothing, on any machine. What is not derived: decisions and options, because whether the assistant chose one approach over another is a judgement about prose, and that pass belongs to an agent reading the imported graph.

The Core Bet

Decisions are the unit of institutional knowledge. Code is the output; decisions are the input. If we capture decisions systematically, we unlock organizational intelligence that's currently impossible.

Most documentation captures the what. The why is more valuable and almost never captured. Deciduous is a bet that capturing the why is worth the effort.

If that bet pays off, the decision graph becomes the most valuable artifact in a codebase. More valuable than tests (which verify behavior) or docs (which explain usage). Because the graph explains intent—and intent is what you need to maintain and extend software over time.

Built by a human and an AI, documented in real-time, queryable forever.
